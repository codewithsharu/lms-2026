# Product Requirements Document (PRD)
# College Assessment Platform

**Document Version:** 1.0  
**Last Updated:** March 7, 2026  
**Status:** Draft

---

## 1. Executive Summary

### 1.1 Product Overview
A scalable web-based assessment platform designed for colleges to conduct MCQ and coding-based tests. The platform supports 5,000 concurrent users with role-based access control for Admins, Teachers, and Students.

### 1.2 Tech Stack
| Component | Technology |
|-----------|------------|
| Frontend | React.js |
| Backend | Node.js, Express.js |
| Database | Supabase (PostgreSQL) |
| Authentication | Supabase Auth |
| Real-time | Supabase Realtime |
| Image Storage | Cloudinary |
| Code Execution | Isolated sandbox (Judge0/Custom) |

### 1.3 Key Objectives
- Handle 5,000 concurrent users seamlessly
- Provide comprehensive audit logging for all platform activities
- Support MCQ and coding-based assessments
- Enable hierarchical organization: Classes → Sections → Zones
- Deliver real-time analytics and progress tracking

## 2. User Roles & Permissions

### 2.1 Admin
**Description:** Super user with complete platform control

**Capabilities:**
| Feature | Description |
|---------|-------------|
| User Management | Create, update, delete, and manage all users (Students & Teachers) |
| Bulk User Import | Upload users via Excel/CSV for bulk creation |
| Access Control | Assign and revoke permissions for all users |
| Organizational Structure | Create and manage Classes → Sections → Zones |
| Teacher Assignment | Assign teachers to specific Classes/Sections/Zones |
| Analytics Dashboard | View platform-wide analytics and metrics |
| Audit Logs | Access complete audit trail of all platform activities |
| System Configuration | Manage platform settings and configurations |

### 2.2 Teacher
**Description:** Assessment creator and student manager within assigned scope

**Capabilities:**
| Feature | Description |
|---------|-------------|
| Assessment Creation | Create MCQ and Coding assessments |
| Question Bank | Build and manage question repository |
| Draft & Publish | Save assessments as drafts, publish when ready |
| Student Management | Manage students within assigned Classes/Sections/Zones |
| Analytics Dashboard | View assessment performance and student analytics |
| Grading | Review and grade student submissions |
| Limited Access | Access restricted to assigned organizational units only |

### 2.3 Student
**Description:** Assessment taker with progress visibility

**Capabilities:**
| Feature | Description |
|---------|-------------|
| Attempt Assessments | Take assigned MCQ and Coding tests |
| View Progress | Track personal assessment progress |
| Leaderboard | Compare progress with peers |
| Results | View detailed results and feedback |
| History | Access past assessment attempts |

## 3. Organizational Hierarchy

```
┌─────────────────────────────────────────────────────────────┐
│                         ADMIN                                │
│                    (Platform Level)                          │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                        CLASSES                               │
│              (e.g., CSE-2024, ECE-2024)                     │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                       SECTIONS                               │
│                  (e.g., A, B, C, D)                          │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                         ZONES                                │
│                  🔵 Blue  🔴 Red  🟢 Green                   │
└─────────────────────────────────────────────────────────────┘
```

### 3.1 Hierarchy Rules
- One Class can have multiple Sections
- One Section can have multiple Zones (Blue, Red, Green)
- Teachers are assigned at any level (Class/Section/Zone)
- Students belong to a specific Zone within a Section within a Class
- Permissions cascade downward (Class access includes all Sections and Zones)

Required Excel Template Columns:
| Column | Required | Description |
|--------|----------|-------------|
| user_type | Yes | "student" or "teacher" |

| email | Yes | Unique email address |
| phone | No | Contact number |
| password | No | Auto-generated if empty |

| section_name | Students | Assigned section |

**Bulk Upload Flow:**
1. Download template
2. Fill user data
3. Upload file
4. System validates data
5. Preview valid/invalid entries
6. Confirm upload
7. System creates users & sends credentials via email

### 6.2 Audit Logging Middleware

```javascript
// Every API request passes through this middleware
const auditMiddleware = async (req, res, next) => {
  const startTime = Date.now();
  
  // Capture original response
  const originalSend = res.send;
  res.send = function(body) {
    res.responseBody = body;
    return originalSend.apply(this, arguments);
  };

  res.on('finish', async () => {
    await createAuditLog({
      timestamp: new Date(),
      user_id: req.user?.id,
      user_email: req.user?.email,
      user_role: req.user?.role,
      action_type: getActionType(req.method),
      resource_type: getResourceType(req.path),
      resource_id: req.params?.id,
      api_endpoint: req.originalUrl,
      http_method: req.method,
      request_body: sanitizeBody(req.body),
      response_status: res.statusCode,
      ip_address: req.ip,
      user_agent: req.headers['user-agent'],
      duration_ms: Date.now() - startTime
    });
  });

  next();
};
```

### 8.2 Row Level Security (Supabase RLS)

```sql
-- Example RLS policies

-- Students can only see their own data
CREATE POLICY "Students view own data" ON students
  FOR SELECT USING (auth.uid() = user_id);

-- Teachers can only see students in their assigned classes
CREATE POLICY "Teachers view assigned students" ON students
  FOR SELECT USING (
    EXISTS (
      SELECT 1 FROM teacher_assignments ta
      JOIN teachers t ON t.id = ta.teacher_id
      WHERE t.user_id = auth.uid()
      AND ta.class_id = students.class_id
    )
  );

-- Admin has full access
CREATE POLICY "Admin full access" ON students
  FOR ALL USING (
    EXISTS (
      SELECT 1 FROM users
      WHERE id = auth.uid() AND role = 'admin'
    )
  );
```
